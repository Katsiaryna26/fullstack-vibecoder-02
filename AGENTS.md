# Архитектурные правила

Для backend-кода, включая Supabase Edge Functions, придерживайтесь трёхслойной архитектуры:

1. **Presentation** — Edge Function. Она разбирает HTTP-запрос, проверяет формат входных данных, вызывает сценарий приложения и преобразует результат или ошибку в HTTP-ответ. Здесь не должно быть бизнес-правил и запросов к PostgreSQL.
2. **Application** — сценарии (use cases). Каждый use case оформляйте отдельным объектом с методом `execute` (в TypeScript — `execute(...)`). Он координирует выполнение операции и содержит прикладные правила, но не зависит от HTTP и деталей PostgreSQL.
3. **Infrastructure** — репозитории и прочие адаптеры внешних систем. Доступ к PostgreSQL/Supabase, включая построение запросов, выбор колонок, сортировку, преобразование строк БД и обработку ошибок драйвера, размещайте в репозиториях. Use case импортирует и напрямую вызывает нужные репозитории.

При добавлении или изменении backend-операции сохраняйте простое направление импортов: Edge Function импортирует use case, use case импортирует используемые им репозитории. Не вводите dependency injection, контейнеры зависимостей или отдельные контракты/интерфейсы репозиториев. Общие HTTP- и Supabase-клиентские утилиты сами по себе не являются поводом помещать бизнес-логику или SQL-запросы в Edge Function.
